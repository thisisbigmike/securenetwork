01 / Project Overview

From a flat network to controlled trust zones

The project addresses unauthorized access and lateral movement by splitting an organizational LAN into isolated broadcast domains, then governing inter-department traffic with routing, ACLs and firewall rules.

01

Problem

A flat or poorly protected network can expose organizational systems and information to unauthorized access, misuse and network-based attacks.

02

Aim

Design and implement a secured network model that reduces unauthorized access by separating users and enforcing controlled communication between network segments.

03

Method

Build and configure the model in Cisco Packet Tracer using VLANs, IEEE 802.1Q subinterfaces, routing, an ASA firewall and access-control logic.

04

Outcome

Five departmental VLANs were configured and tested. Inter-department communication is treated as restricted unless the security policy explicitly permits it.

02 / Architecture

Layered network security architecture

The design combines segmentation at Layer 2 with routed policy enforcement at Layer 3 and a perimeter firewall for traffic entering or leaving protected zones.

Logical model
Trust boundary: each VLAN is a separate broadcast domain. Inter-VLAN traffic must traverse a policy enforcement point before reaching another department.
01

Segmentation

Departmental users and resources are divided into five VLANs to reduce broadcast scope and constrain lateral access.

02

Inter-VLAN Routing

Router subinterfaces use 802.1Q encapsulation with one gateway per departmental subnet.

03

Traffic Filtering

Extended ACLs are intended to permit required flows and deny unauthorized cross-VLAN communication.

04

Perimeter Control

The ASA firewall adds a boundary between trusted internal traffic and less trusted external networks.

06 / Findings & Limitations

What the model demonstrates, and what it does not

A credible project presentation should distinguish a successful simulation from production-grade security assurance.

Demonstrated

Segmentation reduces unnecessary reachability

Five departmental groups are separated logically, and inter-VLAN communication can be subjected to explicit routing and filtering policy rather than unrestricted lateral access.

Limitation

Simulation is not production validation

The design was tested in Cisco Packet Tracer. Real hardware, production traffic, device failure, throughput, logging and adversarial testing remain outside the demonstrated scope.

Residual risk

VLAN 1 remains a management access point

The report specifically identifies VLAN 1 as a path through which the internal management domain may still be exposed. VLAN segmentation alone is therefore not sufficient.

Recommended next steps

Strengthen the design before real-world deployment

01

Harden switching infrastructure. Restrict administrative access and apply basic switch-security controls.

02

Use centralized VLAN management carefully. The report recommends VLAN Trunking Protocol for centralized VLAN database control and maintenance.

03

Place extended ACLs correctly. Apply rules to the correct router interface or subinterface and in the correct inbound or outbound direction.

04

Reduce reliance on VLAN 1. Move management and native VLAN roles to dedicated non-default VLANs in a production design.

05

Improve cybersecurity awareness. Technical controls should be supported by public and organizational education on cybercrime risks.
